## 2. Audit principles used for the proposal

Same principles as the first pass, with the coverage thresholds updated to the current `jest.config.js`.

1. **One owner per rule.** A behaviour is asserted once, at the lowest layer that owns it (domain → application → infrastructure → presentation → e2e). Higher layers only test *wiring*, not the rule again.
2. **Coverage thresholds are a hard constraint** (`jest.config.js`): global 85 % stmts / 80 % branches / 80 % functions / 85 % lines; `src/shared` 85/80; domain 95/90; infrastructure 90/85; application 85/80; presentation 70 % stmts. Domain-layer tests are therefore almost never proposed for removal.
3. **Drop tests that cannot fail meaningfully:** CSS-class assertions, layout/height assertions in jsdom (no layout engine), assertions of third-party library behaviour.
4. **Drop tests of test doubles.** (All of these were removed in the first pass.)
5. **Shared-mechanism tests are not repeated per gateway.** Frame ownership, closed-socket reporting and unsubscribe belong to `MessageBus` / `SocketClient`; `ws-messaging.gateway.test` keeps the single canary.
6. **MERGE** means the assertion is still valuable but should become a case in a sibling (usually `it.each`) rather than a separate `it`. New in this pass: an `it.each` whose parameters are never read is also MERGE — it runs the same body N times.
7. **REVIEW** flags a likely cross-layer duplicate where the higher-layer test *might* still cover unique wiring (drawer close, URL param, focus). A human should decide.
8. **Component-level axe tests are kept.** They overlap with the e2e accessibility route matrix but are cheap and fail in the unit suite. Optional further cut where the e2e matrix covers the same route: ChatPanel, Transcript, ConversationSidebar, knowledge-routes, PresetPromptBar, and the new `review route accessibility` table (feedback queue, reviewed).
